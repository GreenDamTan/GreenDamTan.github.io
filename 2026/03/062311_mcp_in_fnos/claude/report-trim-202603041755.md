## 1. 概述

`trim` 是 fnOS (trimOS) 的**核心服务框架**，负责:
- 创建 UDS (Unix Domain Socket) 监听客户端连接
- 加载 `.hdl` handler 插件
- 通过 WebSocket 协议接收和分发 RPC 请求
- 管理认证 (token/RSA/AES)
- 提供 handler 间接口注册与查询机制

所有 `.hdl` handler（如 user.hdl, sysinfo.hdl 等）均由此框架动态加载和调度。

### 关键文件路径

| 路径 | 说明 |
|------|------|
| `/run/trim_cgi.socket` | UDS 监听套接字（框架创建） |
| `/run/trim.pid` | PID 锁文件 |
| `/usr/trim/logs/trim.log` | 日志文件（spdlog rotating） |
| `/usr/trim/etc/rsa_private_key.pem` | RSA 私钥 |
| `/tmp/trim.nosign` | 认证旁路标志文件 |
| `<app_path>/handlers/` | handler 插件目录 |

### 关键依赖库

- **PPJson**: JSON 解析/序列化
- **OpenSSL**: RSA/AES/SHA256/HMAC 加密
- **spdlog**: 日志（rotating file sink）
- **epoll**: I/O 多路复用
- **dlopen/dlsym**: handler 动态加载

## 2. main() — 框架入口

**地址**: `0xf120` (大小: 0x1867)

### 启动流程

```
1. 初始化日志
   - rotating logger → /usr/trim/logs/trim.log
   - verbose 模式: 100MB × 10 个文件
   - normal 模式: 1MB × 5 个文件

2. 检查 -t 参数（测试模式）

3. 检查 PID 文件 /run/trim.pid
   - 如已存在 → 退出

4. 设置 OOM score adj = -1000（防止被 OOM killer 杀死）

5. srand(time(0))

6. 调用 load_conf()       → 加载配置（线程数/连接数）
7. 调用 load_interfaces()  → 注册框架 API
8. 调用 load_handlers()    → 加载 .hdl 插件

9. 查询 "query_token_by_session" 接口

10. 创建 UDS 套接字
    - socket(AF_UNIX, SOCK_STREAM, 0)
    - bind("/run/trim_cgi.socket")
    - chmod(0666)  ← 任何进程可连接
    - listen()

11. 创建 handler threads（数量 = handler_thread_count）
12. 创建 worker threads（数量 = worker_count）

13. 主循环:
    - sleep(1)
    - 调用 onTimerLoop 回调
    - 每 60s 调用 logstate()
    - 每 ~10s 调用 malloc_trim(0)
```

### 信号处理
- `SIGPIPE` → SIG_IGN（忽略管道断开）

## 3. load_conf() — 配置初始化

**地址**: `0x46bf0`

根据 CPU 核心数动态计算线程配置:

```c
int cpu_count = sysconf(_SC_NPROCESSORS_ONLN);  // 获取 CPU 数

// handler 线程数 = min(cpu_count, 255)
handler_thread_count = min(cpu_count, 255);

// worker 线程数
if (cpu_count <= 3) {
    worker_count = 1;
} else {
    worker_count = (int)sqrt((double)cpu_count);
}

// 每个 worker 分配 384 字节上下文
// 内含 4 个 recursive mutex

max_connections = 10000;            // 最大连接数
connection_timeout = 300;           // 连接超时 (秒)
packet_timeout = 60;                // 包超时 (秒)
```

### TCP 选项标志 (byte_72314)
- bit 0: `TCP_NODELAY`
- bit 1: `TCP_QUICKACK`

## 5. load_handlers() — Handler 插件加载

**地址**: `0x129a0` (大小: 0xd7c)

### 加载流程

```c
DIR *dir = opendir("<app_path>/handlers/");
for (each regular file in dir) {
    void *handle = dlopen(file, RTLD_NOW);
    if (!handle) {
        // 打印 "load handler '%s' failed (dlopen: %s).\n"
        continue;
    }

    // 查找符号
    func_init           = dlsym(handle, "init");
    func_handler        = dlsym(handle, "handler");
    func_before_init    = dlsym(handle, "before_init");
    func_onSessionStart = dlsym(handle, "onSessionStart");
    func_onSessionEnd   = dlsym(handle, "onSessionEnd");
    func_onTimerLoop    = dlsym(handle, "onTimerLoop");

    if (!func_init) {
        // 打印 "load handler '%s' failed (no init func).\n"
        continue;
    }

    // 阶段1: before_init — 注册自定义接口
    if (func_before_init)
        func_before_init(register_interface);

    // 阶段2: init — 获取 handler 名称
    const char *name = func_init(queryinterface);

    // 将 name → func_handler 存入 Rb-tree (unk_72328)
    handler_map[name] = func_handler;

    // 存储回调到数组
    session_start_callbacks[] = func_onSessionStart;
    session_end_callbacks[]   = func_onSessionEnd;
    timer_loop_callbacks[]    = func_onTimerLoop;

    // 打印 "load handler '%s' OK!\n"
}
```

### Handler 生命周期

## 6. register_interface() / queryinterface() — 接口注册与查询

### register_interface()

**地址**: `0x509a0`

```c
int register_interface(char *name, void *func_ptr) {
    // 在全局 map (unk_72358) 中查找
    if (map.find(name) != map.end()) {
        fprintf(stderr, "register_interface: '%s' is already exists.\n", name);
        return -1;
    }
    map[name] = func_ptr;
    return 0;
}
```

### queryinterface()

**地址**: `0x503d0`

```c
void* queryinterface(const char *name) {
    if (!name) return NULL;
    auto it = map.find(name);
    if (it != map.end()) {
        return it->second;
    }
    fprintf(stderr, "query_interface: '%s' is not exists.\n", name);
    return NULL;
}
```

> handler 在 `init()` 中通过 `queryinterface()` 获取框架提供的 `send_string`、`g_logger` 等函数指针。
> handler 也可在 `before_init()` 中通过 `register_interface()` 注册自己的接口，供其他 handler 查询使用。

## 7. n_worker_thread() — Worker 线程

**地址**: `0x4cf70` (大小: 0xba7)

线程名: `"worker-thread"`

### 职责
- **epoll I/O 多路复用**，管理所有客户端连接
- 接受新连接 (accept4)
- 处理读/写/错误事件
- 分发 WebSocket 数据包给 handler 线程
- 发送响应数据

### 核心逻辑

```c
void n_worker_thread(void *arg) {
    int worker_id = HIDWORD(arg);
    worker_ctx = &worker_array[worker_id];

    // 创建 epoll
    worker_ctx->epoll_fd = epoll_create1(EPOLL_CLOEXEC);

    // 监听 UDS 套接字 + eventfd
    epoll_ctl(epoll_fd, EPOLL_CTL_ADD, listen_socket, EPOLLIN|EPOLLET);
    epoll_ctl(epoll_fd, EPOLL_CTL_ADD, event_fd, EPOLLHUP);

    // 等待所有 worker 就绪
    while (ready_count < worker_count) usleep(10000);

    while (1) {
        int n = epoll_wait(epoll_fd, events, max_events, 1000);

        for (each event) {
            if (fd == event_fd) {
                // 处理发送队列（从 handler 线程来的响应）
                // 处理新 socket 注册
            }
            else if (fd == listen_socket) {
                // accept4 新连接 (SOCK_CLOEXEC | SOCK_NONBLOCK)
                // 设置 TCP_NODELAY, TCP_QUICKACK
                // 分配给随机 worker: rand() % worker_count
            }
            else {
                // 客户端事件
                if (EPOLLERR | EPOLLHUP | EPOLLRDHUP) → client_close()
                if (EPOLLIN)  → client_recv()
                if (EPOLLOUT) → client_send()
            }
        }

        // 定期清理超时连接
        recycle(worker_id);
    }
}
```

### Session ID 编码

```
Session ID (8 bytes):
┌──────────┬──────────┬──────────────────────┐
│ worker   │ socket   │ atomic counter       │
│ index    │ fd       │ (单调递增)            │
│ (8 bits) │ (24 bits)│ (32 bits)            │
└──────────┴──────────┴──────────────────────┘
  byte 7    bytes 4-6    bytes 0-3
```

生成方式: `(worker_idx << 56) | (fd << 32) | atomic_counter++`

## 8. handler_thread() — Handler 线程

**地址**: `0x549a0` (大小: 0x1b2)

线程名: `"handler-thread"`

### 职责
- 从全局包队列 (g_ws_packets_queue) 中取出 WebSocket 数据包
- 验证 session 仍然有效
- 管理流控 (resume_recv)
- 调用 `handle_websocket_packet()` 进行实际处理

```c
void handler_thread(void *arg) {
    while (1) {
        // 等待条件变量
        pthread_mutex_lock(&queue_mutex);
        while (!g_ws_packets_queue)
            pthread_cond_wait(&queue_cond, &queue_mutex);

        // 取出队列头
        packet = g_ws_packets_queue;
        g_ws_packets_queue = packet->next;
        pthread_mutex_unlock(&queue_mutex);

        // 验证 session 存在且有效
        worker_ctx = &worker_array[session_worker_index];
        connection = find_connection(worker_ctx, session_id);

        if (connection && connection.active) {
            // 更新流控计数
            connection.pending_packets--;
            connection.pending_count--;

            // 如果之前暂停了接收，且积压已降低
            if (connection.paused && pending_count <= 9 && pending_bytes <= 0x1FFFF) {
                resume_recv(session_id);
                connection.paused = false;
            }

            handle_websocket_packet(packet);
        }

        free(packet->data);
        free(packet);
    }
}
```

## 9. handle_websocket_packet() — 请求分发（核心）

**地址**: `0x53c00` (大小: 0xd97)

这是整个框架最核心的函数，处理所有 RPC 请求的解析、认证和分发。

### 请求格式

WebSocket 数据包格式:
```
[base64_token(44字节)]{json_payload}
```

或无认证格式:
```
{json_payload}
```

### 处理流程

```
1. 在数据中查找 '{' 字符位置
   - s2 = '{' 之前的字节数（token 长度）
   - 如果 s2 == 44 → 有 base64 token
   - 如果 s2 == 0  → 无 token

2. 解析 JSON，提取 "req" 字段

3. 如果 req == "encrypted":
   → 加密信封处理（见第 10 节）

4. 检查 "si" 字段是否匹配 session_id

5. Handler 分发:
   - 找 req 中第一个 '.' 的位置
   - 截断取 handler 名称
   - 在 Rb-tree (unk_72328) 中查找
   - 未找到 → 返回错误码 10000002

6. 认证检查:
   a. 如果 s2 == 44:
      - base64 解码 (44字节 → 32字节)
      - AES 解密 + HMAC-SHA256 验证
   b. 如果 s2 == 0:
      - 检查 no_sign() → /tmp/trim.nosign
      - 或检查 nosig_whitelist(req)
   c. 认证失败 → 拒绝请求

7. 调用 handler:
   handler(session_id, fd, data_len, json_data, extra_data)

8. 记录慢请求 (>9ms)
```

### Handler 分发详解

```c
// req = "user.info"
int dot_pos = req.find(".");     // dot_pos = 4
string handler_name = req.substr(0, dot_pos);  // "user"

// 在 Rb-tree 中查找 "user" → handler 函数指针
auto it = handler_map.find(handler_name);
if (it == handler_map.end()) {
    // 返回 error 10000002 "Not found req field."
    return;
}
handler_func = it->second;
handler_func(session_id, fd, len, json, extra);
```

> **重要**: 框架只截取第一个 `.` 之前的部分作为 handler 名称。
> handler 内部再自行解析 `req` 字段来获取具体方法名。

## 10. 加密请求处理

当 `req == "encrypted"` 时，进入加密信封处理:

### 信封 JSON 格式
```json
{
    "req": "encrypted",
    "key": "<RSA_encrypted_AES_key_base64>",
    "data": "<AES_encrypted_payload_base64>"
}
```

### 解密流程

```
1. 读取 RSA 私钥 /usr/trim/etc/rsa_private_key.pem
   - 使用 TLS (Thread Local Storage) 缓存
   - 通过 mtime 检测文件变更，变更时重新读取

2. RSA 解密 "key" 字段 → 得到 AES 密钥

3. AES-256-CBC 解密 "data" 字段 → 得到明文 JSON

4. 重新解析明文 JSON，继续正常分发流程
```

### 加密函数

| 函数 | 地址 | 说明 |
|------|------|------|
| `aes_encrypt()` | `0x3fb20` | AES-256-CBC 加密 (EVP) |
| `aes_decrypt()` | `0x3fc10` | AES-256-CBC 解密 (EVP) |
| `rsa_sign()` | `0x3f780` | SHA256 + RSA 签名 |

## 11. 认证机制

### Token 认证

```
WebSocket 数据: [base64_token(44字节)]{json}
```

1. base64 解码 44 字节 → 32 字节原始 token
2. 使用 `get_secret_aeskey()` 获取 AES 密钥
3. AES 解密 token
4. HMAC-SHA256 验证完整性
5. 通过 `query_token_by_session` 接口验证 session

### get_secret_aeskey()

**地址**: `0x54b90`

```c
unsigned char* get_secret_aeskey() {
    struct stat st;
    stat64("/usr/trim/etc/rsa_private_key.pem", &st);

    // TLS 缓存: 检查 mtime 是否变更
    if (st.st_mtime != cached_mtime) {
        int fd = open("/usr/trim/etc/rsa_private_key.pem", O_CLOEXEC);
        lseek(fd, 100, SEEK_SET);     // 跳到偏移 100
        read(fd, tls_buffer, 32);      // 读取 32 字节作为 AES 密钥
        close(fd);
        cached_mtime = st.st_mtime;
        printf("[%lu]cache secret from file\n", pthread_self());
    }
    return tls_buffer;  // 返回 TLS 中的 32 字节密钥
}
```

> **注意**: AES 密钥直接从 RSA 私钥文件偏移 100 处取 32 字节。这意味着密钥是 PEM 文件 base64 编码内容的一部分。

### no_sign() — 认证旁路

**地址**: `0x526c0`

```c
bool no_sign() {
    struct stat st;
    int ret = stat("/tmp/trim.nosign", &st);
    // 文件存在 且 属于 root (uid == 0)
    bool result = (ret | st.st_uid) == 0;
    cached_nosign = result;
    return result;
}
```

当 `/tmp/trim.nosign` 存在且属于 root 时，**所有无 token 的请求都会跳过认证**。

## 12. client_recv() — 数据接收

**地址**: `0x42dc0` (大小: 0x39c)

### 协议识别

```c
ssize_t client_recv(connection_ctx_t *ctx) {
    // 循环 recv (MSG_DONTWAIT)，最多 64KB 一批
    while (1) {
        ssize_t n = recv(ctx->fd, ctx->buf + ctx->buf_used, buf_size - buf_used, MSG_DONTWAIT);

        // 解析缓冲区
        if (buf_used > 3 && *(uint32_t*)buf == 0x20544547) {
            // "GET " (0x47455420) → HTTP 请求
            // 查找 "\r\n\r\n" (0x0A0D0A0D) 结尾
            parse_http_packet(ctx);  // WebSocket 升级握手
        } else {
            // WebSocket 帧解析
            // 支持 payload 长度: 7-bit, 16-bit (126), 64-bit (127)
            // 最大单帧: 0x101000 (约 1MB)
            process_websocket_packet(ctx);
        }

        // 流控: 累计 > 64KB 时暂停 epoll 监听
        if (total > 0xFFFF) {
            unsafe_modify_epoll_event(ctx);  // 暂停 EPOLLIN
            return 1;
        }
    }
}
```

### WebSocket 帧格式

```
byte 0: FIN(1) + RSV(3) + Opcode(4)
  - opcode 0x8 = close → 断开连接
  - opcode 0x1 = text
  - opcode 0x2 = binary

byte 1: MASK(1) + Payload length(7)
  - 126 → 后续 2 字节为长度
  - 127 → 后续 8 字节为长度

如果 MASK=1: 后续 4 字节为 mask key
payload data
```

## 13. recycle() — 超时回收

**地址**: `0x49dc0` (大小: 0x1d1)

```c
void recycle(int worker_id) {
    for (each connection in worker[worker_id]) {
        if (!connection.active) continue;
        if (connection.timeout == -1) continue;

        // 检查包超时（收到最后一个包到现在的时间）
        if (connection.last_packet_ctx &&
            current_time - last_packet_time > packet_timeout) {
            log("Close packet-timeout socket:{},session={}");
            shutdown(connection.fd, SHUT_RDWR);
            continue;
        }

        // 检查连接超时
        if (current_time - connection.timeout > connection_timeout) {
            log("Close timeout socket:{},session={}");
            shutdown(connection.fd, SHUT_RDWR);
        }
    }
}
```

## 15. websocket_send() — WebSocket 发送

**地址**: `0x50f20` (大小: 0x197)

```c
int websocket_send(uint64_t session_id, const uint8_t *data, size_t len, bool is_text) {
    int worker_idx = (session_id >> 56) & 0xFF;
    if (worker_idx >= worker_count) return -1;
    if (!data || !len) return -1;

    // 封装 WebSocket 帧
    packet_list = pack_websocket_packet(data, len, is_text);
    if (!packet_list) return -1;

    // 分配发送任务
    task = malloc(0x20);
    task->session_id = session_id;
    task->fd = (session_id >> 32) & 0xFFFFFF;
    task->packets = packet_list;

    // 加入 worker 的发送队列（加锁）
    worker_ctx = &worker_array[worker_idx];
    pthread_mutex_lock(&worker_ctx->send_mutex);
    enqueue(worker_ctx->send_queue, task);
    pthread_mutex_unlock(&worker_ctx->send_mutex);

    // 通知 worker 线程
    post_eventfd(worker_idx);
    return 0;
}
```

### send_string_ex()

**地址**: `0x513f0`

```c
int send_string_ex(uint64_t session, const char *msg, size_t max_len) {
    size_t len = strlen(msg);
    if (!len) return -1;

    // 流控检查
    if (sendqueue_inc(session, len, max_len) != 0)
        return QUEUE_FULL;

    int ret = websocket_send(session, msg, len, true);  // is_text=true
    if (ret != 0) sendqueue_dec(session, len);

    // 日志: "-session:{}[{}] {}" (截断到 1023 字节)
    return ret;
}
```

## 19. 安全相关发现

### 认证旁路
- `/tmp/trim.nosign` 文件（root 拥有）存在时，所有无 token 请求跳过认证
- 15 个白名单方法无需任何认证即可调用

### AES 密钥来源
- 直接从 RSA 私钥 PEM 文件偏移 100 读取 32 字节
- 本质是 PEM base64 编码内容的一部分
- 所有线程通过 TLS 缓存此密钥

### 连接管理
- UDS socket chmod 0666 — 系统上任何进程均可连接
- max_connections 默认 10000
- WebSocket 最大单帧约 1MB (0x101000)

### 错误码

| 错误码 | 含义 |
|--------|------|
| 10000002 | Handler not found (req 中无匹配的 handler 名) |
